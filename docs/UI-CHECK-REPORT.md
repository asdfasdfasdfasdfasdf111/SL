## 三、坐标之谜：AX 报告坐标偏移约一个窗口宽度

### 现象
窗口报告位置为 `@644,92 800x618`（x 范围 644 ~ 1444），但元素树中大量元素报出远超该范围的坐标：

| 元素 | AX 报告坐标 |
|---|---|
| 自动选择 Java | @2133,247 |
| 分类「模组」 | @2244,364 |
| 卡片网格 | @2440,286 |
| 滚动条 | @3028,286 |

### 实测结论
上述元素在**界面上的实际渲染位置是正确的**（截图可见它们位于窗口内），但 AX 报出的坐标比实际位置**大约 800，正好等于窗口宽度**。

对比验证：
- 「启动游戏」按钮：AX 报 @706，截图实测约 @754 → 基本一致
- 版本列表项「1.20.1-Forge」：AX 报 @1476，截图实测约 @693 → **相差 783（≈ 窗口宽度）**

即：**不同类型的元素，AX 坐标基准不一致**，一部分偏移了一个窗口宽度。

### 影响
- **按坐标点击会点错位置**：拿 AX 报的坐标直接点击，会落到右侧约 800px 处（可能是别的元素，甚至窗口外/屏幕外）
- 这正是「坐标不在窗口上」的成因

### 规避方式（已在工具中采用）
使用 **元素级操作**：定位到元素后执行 `AXPress`，全程不涉及坐标计算，不受该偏移影响。
`scripts/ui-click.swift` 即按此实现，实测各页面导航切换均成功。

### 附带发现
`AXScrollToVisible` 这一动作在新版 SDK 中已不再导出常量 `kAXScrollToVisibleAction`，须使用其字符串名调用。
